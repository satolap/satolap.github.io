Versioning and releases

One version covers both generated catalogs and the verified modules. Versions follow the interface changes that the release gate detects: each release's notes summarise them, and the exact list is in interface-changes.json.

What to pin

Pin a patch-only constraint such as ~> {{MINOR}}.0 to take fixes only. Before a new minor version, read the release's breaking changes and migration notes; blocking changes are published only when a reviewed release decision accepts them.

Beta modules

Microsoft Graph beta APIs are previews and can change incompatibly; Microsoft recommends v1.0 for production. See Microsoft's versioning and support policy.

Release integrity you can audit

Every published catalog passes these automated checks before its release tag is created.

  1. Source manifests and cached metadata are checked against their recorded revisions and SHA-256 hashes.
  2. Python regression tests cover schema reconciliation, type generation, classification, deterministic output, safe archive handling and atomic publication.
  3. terraform fmt -check, terraform init -backend=false and terraform validate run for every generated and verified module, against the exact provider versions in the release manifest.
  4. Credential-free terraform test suites use provider mocks. They check Graph URL construction, typed request bodies, omission of null optional properties, validation failures and verified relationship behaviour, without contacting a tenant.
  5. The release workflow rebuilds the archives from the tagged commit and requires their byte-level SHA-256 checksums to match the tested artifacts. It then creates a build provenance attestation for every release asset.

A daily scheduled workflow rebuilds every published release and fails if a tag, an asset digest or an attestation no longer matches. release-manifest.json records the upstream metadata commit, provider versions, dependency hashes and the complete input fingerprint, so the inputs of any release can be audited.

Mock tests and schema validation do not prove that a caller has the required Microsoft Graph permissions, licence or tenant configuration. Each module's README links to the API documentation for those requirements. Live-tenant integration checks are separate and opt-in; a verified module's page states whether it has one.
