Support and policies

Support runs in the open, on GitHub. The public repository publishes these channels and commitments.

Problems and module requests

Open a GitHub issue with the release tag and module path, your Terraform and provider versions, a minimal configuration, the expected and actual result, and sanitised logs. Templates exist for bug reports, module requests and accessibility barriers.

Security

Report a suspected vulnerability privately through GitHub's vulnerability reporting, never in a public issue. Expect an initial acknowledgement within seven days. Fixes are applied to the latest release and main; older tags are immutable, so upgrade after a fix is published. Read the security policy.

Provider and Graph issues

Problems in the microsoft/msgraph provider or in the Microsoft Graph API itself belong upstream, in the provider's issue tracker.

Changing a module

The module trees are published from a validated pipeline, so pull requests that edit them cannot be accepted: open an issue describing the change instead. Pull requests are welcome for the public documentation and release tooling. See CONTRIBUTING.md.

Licensing

The code and verified modules are available under the MIT License. Generated interfaces derive from Microsoft Graph metadata (MIT) and documentation (CC BY 4.0); NOTICE lists the upstream notices.

Accessibility

The documentation is plain Markdown with a logical heading structure, descriptive links and text alternatives. Report a barrier with the accessibility report template; the accessibility statement lists known limitations.

Support commitment

Support is public and community-based: GitHub issues for problems and module requests, and private vulnerability reporting with an acknowledgement within seven days. The repository states no other support commitment. Security fixes go to the latest release; see versioning and releases for what to pin.
